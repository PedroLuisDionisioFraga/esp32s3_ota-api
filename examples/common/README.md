# Shared example assets

Files used by every example under `examples/`. This directory is **not** an
ESP-IDF project — there is nothing to build here.

```text
examples/common/
├── ota_server.py   # local HTTPS/HTTP server + self-signed certificate generator
├── certs/
│   ├── ca_cert.pem # embedded into the firmware at build time
│   └── ca_key.pem  # generated by ota_server.py, not versioned
└── ota/            # firmware images to serve
    ├── bootloader.bin
    └── hello_world.bin
```

## Running the server

From any example directory:

```bash
python ../common/ota_server.py
```

That serves `examples/common/ota/` over HTTPS on port `8070`, binding to the
auto-detected LAN IP. The script prints the exact URL to paste into
`idf.py menuconfig -> Example Configuration -> firmware upgrade url endpoint`.

Relative paths are resolved against the script's own directory, not the current
one, so the command above works unchanged from `examples/basic`,
`examples/rollback` and `examples/on_demand`.

To override the defaults:

```bash
python ../common/ota_server.py --host 192.168.1.50 ota 8070 certs
```

- `--host` — bind address, when the auto-detected LAN IP is not the one the
  ESP32 should reach.
- `ota` — directory holding the `.bin` to serve.
- `8070` — port.
- `certs` — directory holding `ca_cert.pem` and `ca_key.pem`.

### Plain HTTP

To serve the image without TLS:

```bash
python ../common/ota_server.py --http
```

No certificate is read or generated, so `certs/` is ignored. The URL the script
prints starts with `http://`; the device only accepts it when built with
`CONFIG_ESP_HTTPS_OTA_ALLOW_HTTP=y` (**Component config → ESP HTTPS OTA → Allow
HTTP for OTA**). The embedded `ca_cert.pem` is simply ignored for an `http://`
URL, so nothing else changes on the firmware side.

`--http` cannot be combined with `--regen-cert` or `--no-gen-cert`. Use it on a
closed test network only: the firmware travels unencrypted and unauthenticated.

## Certificates

The server generates its own self-signed certificate, so **no `openssl`
installation is required** — on Windows or on Linux. Generation uses the
`cryptography` package, which is already part of the ESP-IDF Python
environment.

The certificate is generated when:

- `ca_cert.pem` or `ca_key.pem` is missing (the private key is not versioned,
  so this is what happens on a fresh clone), or
- the existing certificate has expired or was issued for a different IP, or
- `--regen-cert` is passed.

Otherwise the existing pair is reused untouched. Use `--no-gen-cert` to bring
your own certificate and have the script fail instead of overwriting it.

The generated certificate carries the server IP both in the Common Name and in
`subjectAltName`. mbedTLS validates the SAN, so the examples do not need
**Skip server certificate CN fieldcheck** enabled.

### After regenerating: rebuild and reflash

The firmware **embeds `ca_cert.pem` at build time**. A device flashed before the
certificate changed still trusts the old one and the TLS handshake will fail
with `ESP_ERR_ESP_TLS_CERT_PARTIALLY_OK` or a similar handshake error. The
script prints a warning whenever it generates a certificate; when you see it:

```bash
idf.py fullclean build flash monitor
```

### Generating the pair by hand

Not needed, but if you want to replace the generated pair, produce an
equivalent certificate and run the server with `--no-gen-cert`:

```bash
openssl req -x509 -newkey rsa:2048 -keyout ca_key.pem -out ca_cert.pem \
  -days 365 -nodes -subj "/CN=192.168.1.50" -addext "subjectAltName=IP:192.168.1.50"
```

Omitting `-addext subjectAltName` is the usual cause of a certificate that the
device rejects unless CN checking is skipped.

## Firmware images

`ota/` holds the images served to the device. `hello_world.bin` is a prebuilt
payload useful for a first end-to-end test. To serve a firmware you just built,
copy it in:

```bash
cp build/my_project.bin ../common/ota/
```
